# CYF 统一接口规范

**规范版本：1.4（2026-10-24校验必要性与跨端兼容修订；公共protocolVersion仍为1）；状态：目标规范已确定，实现未全量迁移。**

这是 CYF 自有接口的唯一公共规范，适用于前端 ↔ API、API ↔ Agent Runtime，以及内部异步消息和本机控制接口。HTTP、WebSocket、SSE、Unix socket 只承担传输差异，不各自定义一套业务语义。具体影响与已核对源码见 [影响分析](interface-standard-impact-20261014.md)。

实现落点与逐字段改动见 [迁移详设](interface-standard-detailed-design.md)；逐接口库存/关键契约与风险见 [接口目录](interface-catalog/README.md)。详设不得另行改写本文公共定义。

## 1. 权威、范围与落地边界

1. 项目根规则规定安全、发布和操作边界；本文规定接口公共结构与语义；功能契约只补充路由/消息类型、业务字段、状态机、权限、幂等和副作用。冲突必须修正文档及实现，不让调用方猜选一份。
2. 新增/改变 wire 的接口按本文实施。尚未迁移接口属于已知差异，不是第二套获准规范；不改变 wire 的定向缺陷修复可以先按固定现行报文验证，不借故扩大为全系统重构，也不能称其已符合目标规范。
3. 本规范版本不是应用发布版本、协议版本或技能包版本。文档确定不触发代码生成、数据库迁移、服务重启或上线。
4. 按2026-10-24最新授权支持明确边界的版本兼容，取消仅因新增无害字段或已完成历史记录缺少新字段而拒绝的校验。具体可扩展位置、摘要和恢复语义须由业务合同明确；不能猜测未知执行协议或缺失权限。每条链路变更核对实际生产者、消费者与新旧混合测试，不能将局部兼容宣称为全量迁移。
5. 第三方规定的 OAuth、Provider 协议等保留其外部格式，在现有边界适配；不得修改对方协议来追求表面一致。这不是自有业务模块另开方言的许可。

## 2. 一种业务封装，固定传输映射

### 2.1 公共字段

所有自有 JSON 信封采用以下字段，不新增同义别名：

| 字段 | 类型/含义 | 何时出现 |
| --- | --- | --- |
| `protocolVersion` | 正整数；公共信封版本，目标初版为 `1` | JSON 信封必填 |
| `requestId` | 非空不透明字符串；一次逻辑操作的关联标识，不是授权或幂等凭证 | 必填；无上游请求的事件由生产端生成 |
| `data` | 功能契约确定的 JSON 值；业务内容唯一容器 | 必填；无内容为 `null` |
| `code` | 字符串；成功为现有 `E0`，失败为稳定业务/协议错误码 | 响应、处理回执、错误消息必填；请求不填 |
| `msg` | 安全的可读说明；调用方不得据此分支 | 与 `code` 同时出现 |
| `messageType` | 点分小写名称，例如 `work.result.receipt` | WS/SSE/UDS/异步消息必填；HTTP由路由和method确定操作 |
| `messageId` | 不透明字符串；一条逻辑消息的唯一标识，原消息重投不变 | WS/SSE/UDS/异步消息必填 |
| `correlationId` | 被回复消息的 `messageId` | 异步响应、ACK、回执必填；首发请求/独立事件不填 |

- `data` 外只放已定义的公共元数据。禁止根级散落业务字段；禁止另一套 `payload`、`body`、`result` 作为信封别名；禁止 `type` 与 `messageType` 同时承担消息类型。
- `data` 内的字段属于具体 DTO/schema。例如数据型技能结果中的 `data` 是明确的业务字段，并非允许重复包一层公共信封。
- 旧 `schemaVersion` 如果是业务对象版本，保留在对应业务对象中；不能把它当公共 `protocolVersion`。业务对象已有闭包摘要，移动位置必须按第8节处置。
- 不引入一层额外 `meta`、`context` 或“万能参数”字典。确需公共字段时修改本文及公共 schema；功能作者不得自行扩展信封。
- 目标响应不含重复 HTTP 状态字段 `status`；HTTP status 由传输层返回。业务对象的 `data.status`/`data.state` 是另一概念，按该资源状态机定义。

### 2.2 HTTP

- JSON body 请求采用 `{protocolVersion, requestId, data}`；JSON 响应采用 `{protocolVersion, requestId, code, msg, data}`。不让单个 Controller 返回裸业务对象或额外包第二层信封。
- GET/HEAD 无 body。资源键位于 path、筛选/分页位于 query，均按 schema 校验；GET 不能通过附带 JSON body 绕过查询字段限制。
- `X-Request-Id` 承载关联标识。body/header 同时提供时必须一致，否则400；无body且无header时服务器生成。响应 header/body 同值；header 不作为权限输入。值需校验，不能把任意头内容直接写日志。
- HTTP 成功使用真实2xx，失败使用真实4xx/5xx；成功不能仅靠 `code` 掩盖失败状态，失败不能 HTTP200+错误内容。HTTP status 与 `code` 的对应关系写进该接口契约。
- 空业务操作默认200、`data:null`；已明确声明204或HEAD的接口按HTTP语义无body，不能假装解析JSON。文件下载和已声明流响应见第7节。
- 复用现有 `JsonResult`/统一异常边界收敛，不新建另一套 Response 家族，也不对任意响应做无差别全局包裹。

```json
{
  "protocolVersion": 1,
  "requestId": "req_demo_1",
  "code": "E0",
  "msg": "ok",
  "data": {"catalogRevision": "12", "items": []}
}
```

### 2.3 WebSocket、异步消息和本机 UDS

- 使用同一 JSON 信封；业务请求与业务事件用 `data`，响应/回执再增加 `code,msg,correlationId`。不把HTTP信封整个塞进另一个消息的 `data`。
- WebSocket 一条文本消息是一份完整JSON；UDS沿用私有流连接的一行UTF-8 JSON请求/一行响应。UDS不是另一套字段规范。
- SSE 每个JSON `data:`承载同一消息信封；若使用SSE `id`/`event`，分别与 `messageId`/`messageType` 一致，不另行改名。断线重放游标由流契约明示，不凭“最后显示的一条”猜测。
- 连接地址、HTTP头、已认证连接属性、Unix socket权限负责传输与身份。不得把认证秘密复制进每条信封。

下例为**目标**安装回执，不是当前线上报文。当前扁平回执不可只改测试就视为已迁移，必须同批修改发送、解析、摘要与回放边界。

```json
{
  "protocolVersion": 1,
  "requestId": "req_install_1",
  "messageType": "work.result.receipt",
  "messageId": "receipt_demo_1",
  "correlationId": "result_demo_1",
  "code": "E0",
  "msg": "ok",
  "data": {
    "receiptStatus": "ACCEPTED",
    "skillInstallationId": "si_demo_1",
    "commandId": "cmd_demo_1",
    "attempt": 1,
    "fencingToken": "1",
    "deliveryEpoch": "1"
  }
}
```

## 3. 字段、类型与序列化

- 字段一律 lowerCamelCase；资源ID使用明确的 `*Id`。枚举值按资源的显式枚举表定义；业务状态/错误原因采用大写下划线，不把显示中文当机器值。
- 不透明资源ID保留原字符串语法（如rti_前缀），不得转数字。数值型ID、代际、revision、fence、sequence、可能超出JavaScript安全整数的Long以十进制字符串传输；消费者不得先转Number再比较。非负值用 `0|[1-9][0-9]*`，正值排除0。不允许符号、空格、指数和前导零。
- `protocolVersion`、业务 `schemaVersion`、`attempt`、`pageNum`、`pageSize`等有明确范围的小整数用JSON number；不接受数字字符串、浮点或布尔强转。每字段必须明确最小/最大有效值，不能凭性能猜资源上限。
- `*At` 时间统一为Unix epoch毫秒、非负安全整数；调用方不传本地日期串或秒值。时间戳没有权限语义；凭据有效期、业务到期日、网络超时必须分开命名和处理。
- 金额/计量不得用二进制浮点表示精确值。金额对象用 `{amountMinor:"123",currency:"CNY"}`；已存在其他单位的业务契约要明确转换，不能仅重命名数值。技能费用登记不因此引入执行扣费或费用准入。
- 摘要字段命名 `*Sha256`，值为64位小写十六进制；不得同名混用裸摘要和 `sha256:` 前缀。历史摘要不能直接改写，见第8节。
- `null` 表示契约允许的“明确无值”；缺省表示可选字段未提供。两者不互换；必填字段不可省略；空列表用 `[]`，不能替换成null或空对象。
- 日期、数值、枚举、大小写不进行隐式归一化以通过认证、摘要或状态校验。拒绝重复JSON key。信封与安全业务DTO默认采用封闭字段集合；明确声明可扩展的DTO位置允许无害新增字段，但不得赋予执行权限或改变原摘要；技能自有参数、标签等可扩展字典只能在该业务schema明确声明的位置出现。

## 4. 身份与标识词典

| 名称 | 唯一语义 |
| --- | --- |
| `tenantId` / `clientId` | 可信认证上下文中的租户/客户端边界 |
| `ownerJiacn` | 资源归属主体，不代表调用方自动具备访问权 |
| `agentId` | Agent稳定标识；有方向时用 `sourceAgentId` / `targetAgentId` |
| `runtimeInstallationId` | Runtime安装身份，不是技能安装 |
| `skillInstallationId` | 指定技能安装记录，不是Runtime安装 |
| `runtimeInstanceId` | 当前传输会话所绑定的Runtime启动实例 |
| `executionRuntimeInstanceId` | 不可变执行事实中的原始启动实例；重连不能覆盖 |
| `sessionGeneration` | 当前认证会话代际，十进制字符串 |
| `executionId` / `commandId` / `orderId` | 执行 / 命令 / 商城订单，不互相充当关联键 |
| `requestId` / `messageId` / `correlationId` | 逻辑操作关联 / 消息标识 / 被回复消息标识 |

- 禁止通用 `installationId` 同时指两类安装，禁止adapter以“注入认证字段”为由覆盖业务中的同名ID或原始执行事实。
- 可信上下文由已验证JWT/Runtime凭据/受信本机连接产生，止于安全适配边界；向服务层传框架无关的类型化上下文。不信任body自报tenant、owner、角色或当前代际。
- wire需携带身份关联字段时只作为待核验声明，与可信上下文逐项匹配，不能提升权限；公开DTO只暴露必要关联信息，不能暴露内部凭据/路径。
- 同Owner不是接任务的统一资格条件；任务授权、资料版本授权、主体认证、租户隔离、安装管理权限仍分别检查。不新增外单功能，不把取消同Owner检查理解为公开所有资料。
- scope不符、过期/撤销凭据、失效fence必须拒绝。凭据签发/刷新接口可按其明确安全契约在私密响应中返回凭据；不得出现在普通业务回执、日志、fixture或公开目录。

## 5. 错误、状态、幂等和恢复

- 成功码唯一 `E0`；错误码均为字符串，既有稳定错误码可沿用，不为统一命名批量重编号。同一错误码的含义、可否重试、调用方动作只能有一种定义。
- HTTP映射：400格式/字段非法；401无有效认证；403已认证但无权限；404资源不可见/不存在（资源ACL防枚举时）；409状态、版本或幂等冲突；422格式正确但业务内容不合法；429明确限流；500内部错误；503依赖暂不可用。不能把所有故障归成404、403或200。
- 响应 `msg` 不含堆栈、SQL、令牌、Provider秘密或其他租户事实；日志保留安全错误码、关联ID、失败阶段及内部异常分类。禁止只有 `false`/`UNKNOWN` 而没有可关联的诊断原因。身份校验不得为了诊断泄露敏感信息。
- `E0` 表示对应接口操作成功，不等于整个业务完成：收件ACK、开始执行、安装结果提交、安装ACTIVE、成果可下载是不同事实。回执必须在对应持久化事务提交后发送。`RECEIVED/STARTED/SUCCEEDED` 等按各自命令状态机解释，不将所有资源状态粗暴统一为一组枚举。
- HTTP产生副作用的可重试操作使用 `Idempotency-Key`；重试保留同一逻辑操作的requestId/key。按可信主体+路由/操作+key绑定规范化业务输入摘要；同key异参409，同key同参返回同一业务结果。新意图才生成新key。
- 异步原消息重投保留messageId及不可变业务内容；requestId不是去重键，回执按correlationId关联原结果。attempt、fence和状态推进由权威状态机决定，不能通过重发任意提升。
- 传输超时/丢回执表示结果未知，不证明未执行。先查询或重放原操作，不能直接新下单、重扣费或强制成功。真实网络超时、身份切换取消保留，不为性能预算强加业务失败期限。
- 技能安装生命周期取决于有效订单/安装状态和授权，不套用任务邀请TTL；签名/认证的真实有效期仍需验证。不能通过修改历史expiresAt实现恢复。

## 6. 路由、分页与版本

- HTTP路径使用资源名；既有已验证路径不因文档发布立即重命名。新查询优先GET；复杂查询确需POST使用明确的查询路由且无副作用。动作使用该资源下明确动作路径，不能用GET进行购买、激活、删除或授权。
- 页码分页请求 `pageNum`（从1开始）、`pageSize`；响应业务值统一 `data:{items:[],pageNum:1,pageSize:20,total:"0"}`。total为十进制字符串；默认/最大pageSize必须由该接口契约和已验证实现给出，本文不设新容量门槛。
- 执行历史/流等已需游标的接口用 `cursor,pageSize` 与 `data:{items:[],nextCursor:null,hasMore:false}`，不伪造total；游标不等于权限，仍检查主体和资源范围。两种分页是明确的查询模式，单个接口不能随机两种返回。
- 公共信封、业务DTO、技能包、应用发布分别版本化。未知协议版本明确拒绝，不回退猜测。破坏性的字段、层级、类型、枚举、摘要变化必须在发布记录标出并同步所有消费者；不能只升级后端让前端兜底。

## 7. 文件、流和外部协议的有限映射

- 二进制上传/下载保持multipart或原始字节，不为了统一JSON把图片/视频/base64塞进信封；上传完成的JSON元数据仍用公共响应。固定fileId/version、MIME、byteLength、sha256，下载重新校验资料ACL；URL不是授权替代品。
- 文件响应明确Content-Type/Disposition、缓存与范围读取策略；开始传输前失败可用统一JSON错误；已开始的字节流不能在尾部拼接JSON伪装正常文件。
- SSE/WebSocket流的开始、分片、终态及错误是明确消息类型；断流不是成功终态，序号/重连按固定契约恢复，不按等待时长伪造完成。
- OAuth、第三方Provider、第三方回调、协议握手、HTTP204/HEAD、公开健康探针等真实外部/传输契约不强套业务信封。使用该映射必须在接口定义中说明原因、生产者和消费者，不得把普通自有JSON接口列为“特殊”。


### 7.1 第三方回调协议保护（2026-10-15用户明确，v1.2补充约束）

**统一的是CYF自有协议，不是微信、GitHub等第三方定义的协议。第三方回调必须逐入口识别并从通用wire改造中排除。**

- 识别包括服务器通知/webhook、验签握手、浏览器OAuth重定向回调和框架注册的回调；不能只搜索名称callback/notify或只统计EXTERNAL_CALLBACK响应模式。HTML_OR_REDIRECT也可能是第三方回调。
- 保持提供方约定的method、已登记path/redirect URI、query/header/body参数位置与名称、大小写、类型、媒体类型、编码、签名/加密原文、状态码、challenge/ACK/重定向以及重试/去重语义。不得加Q/R信封、强制protocolVersion/requestId/Idempotency-Key、把code/state改成内部同义字段，或把有副作用的外部GET机械改POST。
- 第三方回调不要求携带本站用户JWT；仍须保留对应协议的验签、state/防重放、来源与资源绑定等验证。不能以“豁免”为由取消认证，也不能将普通自有管理接口伪装成回调绕过ACL。
- 原始报文先按外部协议验证，再在边界适配成内部命令/事件；内部业务仍遵守本项目隔离、事务、幂等和错误规范。内部requestId可自行生成用于关联，不要求外部生产者回传，不进入对方签名原文。
- ResponseBodyAdvice、统一异常处理、安全过滤链、请求包装、SDK适配、网关和客户端拦截器必须按明确入口/契约分流。成功及失败响应都遵从第三方协议；不得仅豁免成功响应、却把验签失败或重试ACK包成R。
- 登记提供方/协议版本、生产者/消费者、入口、原始输入、鉴权、ACK和业务提交条件及已有实现偏差。**保留外部契约不等于冻结已知错误实现**；发现现实现与第三方规范不符，单独依据对应官方协议/已固定SDK核定修复，不以本次统一规范擅自改协议。
- 当前源码识别及保护清单见[第三方回调清单](interface-catalog/external-callback-contracts.md)和`interface-catalog/external-callback-contracts.json`。未核定条目保持未闭合；部署配置中的动态回调/框架入口不能因未出现在Controller库存而遗漏。

## 8. 持久消息、摘要与协调切换

1. 本次实际调用方已由用户确认为Web、API、Runtime和仓内脚本，无额外外部客户端。核对其实际生产者/消费者、版本与摘要边界；不再以未知外部客户端作为前置阻塞。
2. 摘要/签名必须明确覆盖对象、规范化算法与版本。公共元数据、业务快照、会话证明分开定义；JSON对象键顺序、数值类型、null规则必须有固定fixture。日志脱敏器不能用于发送业务wire或计算摘要。

## 9. 轻量实现与验证要求

- 在既有common契约/异常处理、模块DTO、前端HTTP/消息边界、Runtime codec中收敛。不新增协议服务、网关、注册中心、消息队列或泛化工作流引擎；不让技能包携带平台协议分支。
- 每条接口唯一的业务定义至少含：operation/路由/消息类型、身份及资源权限、完整请求和成功/失败报文、字段类型和必填性、状态及副作用、幂等、错误映射、摘要/版本/恢复边界。
- 机器可读约束与完整fixture放在对应既有契约目录；公共信封只定义一次并被引用。Java/JS不要求使用同一语言库，也不强推新代码生成器，但必须消费同源固定schema/fixture并绑定文件摘要；不得手抄两份样例分别自测。
- 最早反馈必须覆盖实际serializer→完整wire→实际consumer parser，既测请求也测回执；包括错误封装层、重复/未知字段、错误类型、大整数、不同安装ID、重连实例、权限拒绝和幂等重放。mock可模拟外部依赖，不能用mock自造wire替代生产序列化。
- 先定向契约测试，再受影响真实HTTP/WS/UDS及DB事务测试，最后按项目规定正式构建/发布。失败先定位，不能每次重新完整构建碰运气。

## 10. 1.1遗漏校核补充（目标设计修订记录）

本节来自逐接口源码复查，不是当前wire已升级。1.0的五字段信封及protocolVersion=1不变；以下补齐其不充分之处。新设计文档版本为1.1，跨仓交接需绑定1.1及文件摘要，不能继续将1.0称为含全部修订的版本。

1. **HTTP状态不是穷举八个码**：保留410退役、412前置条件失配、415媒体类型不支持、416Range不可满足、428缺少必要前置条件，以及405/406等真实传输状态。204/HEAD/304等无body语义优先，不能附JSON；文件接口可明确声明416无body并保留Content-Range，不将其当JSON解析失败；304仅用于明确缓存契约，no-store接口不凭空新增缓存行为。OPTIONS/CORS预检不得触发业务操作。
2. **202是受理而非业务终态**：目标使用E0和明确operation/state，不能202搭普通错误body，也不能让前端把202当文件/成果已就绪。状态未知须能关联原操作；无法给出恢复依据不能伪报受理成功。已断开连接或开始的流不能用统一异常层制造204成功回执。
3. **幂等不等于回放秘密**：一次性凭据接口可以返回明确的不可重放409及安全恢复信息；不得为同key同结果缓存明文秘密或再次签发。会话签发/租约续期按各自原状态机确定重试效果，不由公共HTTP盲重试。商品订单继续保证原交易幂等。
4. **计量单位有明确词典**：Money仍为`{amountMinor,currency}`。SILVER的minor为micro-silver（每SILVER为1,000,000，来源EconomyConstants），原priceMicro/amountMicro整数一对一映射，不按人民币分转换、不改账本。CNY最小单位与SILVER不可混用，换算不允许浮点或静默舍入。
5. **运行费率不是结算金额**：允许业务CostInfo定义`rate:{amountDecimal,currency,unit}`，amountDecimal是精确非负普通十进制字符串，不用JSON浮点；费用仅登记展示，不新增执行扣费/预算授权。未知费用不是免费，也不是禁止执行的依据。原技能包costInfo与执行摘要隔离，公开投影变更不自动修改签名包。
6. **内容类型优先于Java返回类型**：返回byte[]但实际application/json的自有接口仍须统一信封；真正文件/流才是例外。form、multipart及带私密租约证明的下载POST逐接口定义，不靠返回类型自动豁免。
7. **流恢复标识不能丢失**：SSE id等于messageId时，须按该资源流定义可逆游标映射；重放同事件ID不变。Last-Event-ID校scope及保留窗口，不能随机替换原sequence；只改名称不算完成流迁移。
8. **退役入口不是兼容执行**：已返回410的旧技能写入口仍拒绝，已撤mapping的方法不恢复；历史GET仅做授权后的原事实查询。第三方模块里的自有管理接口不自动享受外部协议豁免。
9. **全系统覆盖以实际producer/consumer为准**：静态扫描的596个显式HTTP method/path、99个Controller只是当前固定源码声明，不等于596个在线端点，也不代表其全部schema/权限/错误/持久语义已核定。准确覆盖与缺口见接口目录。
